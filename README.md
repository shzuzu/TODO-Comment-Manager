## Описание

TODO Comment Manager собирает комментарии `TODO`, `FIXME` и `BUG` из исходного кода в общий список задач. Вместо поиска по всему проекту можно открыть боковую панель, выбрать нужную задачу и сразу перейти к её строке в редакторе.

Плагин помогает отмечать незавершённую работу, расставлять приоритеты и следить за выполнением задач. Он работает локально и не требует аккаунта, сервера или сетевого подключения.

## Установка

1. В VS Code откройте **Extensions → ⋯ → Install from VSIX…**.
2. Выберите `todo-comment-manager-1.1.1.vsix` из папки проекта.
3. Откройте папку с исходным кодом и нажмите значок списка задач в Activity Bar.

Минимальная версия VS Code: **1.96**. Расширение работает локально, без аккаунта, сервера и сетевых запросов.

## Формат комментариев

```ts
// TODO[HIGH]: Добавить проверку входных данных
// FIXME[MEDIUM]: Устранить повторный запрос
// BUG[CRITICAL]: Исправить падение при пустом ответе
// TODO: Обновить документацию
/* TODO[LOW]: Упростить стили */
```

```python
# TODO[HIGH]: Обработать ошибку соединения
```

```html
<!-- FIXME[MEDIUM]: Исправить подпись поля -->
```

Поддерживаются маркеры в верхнем регистре: `TODO`, `FIXME`, `BUG`. Двоеточие необязательно. Приоритеты: **CRITICAL → HIGH → MEDIUM → LOW → без приоритета**. Описание занимает остаток строки или текст до следующего маркера в том же комментарии. Несколько задач в одном комментарии поддерживаются. Обычные строки с текстом `"// TODO: пример"` и код вне комментариев задачами не считаются.

## Панель задач

- **+** — добавить задачу перед выделенной строкой, сохранив код и его отступ. Горячая клавиша: `Ctrl+Alt+T`, на macOS — `Cmd+Alt+T`.
- **Поиск** — подстрока в описании, пути файла, типе или приоритете; регистр не учитывается. Пустой запрос очищает поиск.
- **Фильтры** — несколько типов, приоритетов и статусов. Внутри категории действует ИЛИ, между категориями — И. Пустая категория не ограничивает результат.
- **Обновить** — полный повторный обход; при обычной работе изменения отслеживаются автоматически.
- Меню **⋯** — группировка по файлам / типам / приоритетам / статусам, плоский список, сортировка, сброс фильтров и статистика.
- Щелчок по задаче открывает файл и выделяет соответствующий комментарий.
- Кнопка у задачи меняет статус. Контекстное меню позволяет редактировать тип, приоритет и описание или удалить комментарий. Удаление требует подтверждения; изменения поддерживают стандартный Undo.

Типы различаются значками и текстом, приоритеты — цветом и подписью. Цвета берутся из темы VS Code. Статус также отображается текстом и значком. Счётчик в заголовке показывает видимые / все задачи. Поиск, фильтры, группировка и сортировка сохраняются для рабочего пространства.

## Подсветка в редакторе

Подсветка включена по умолчанию. Кнопка **с глазом** в заголовке панели задач отключает её; кнопка **с перечёркнутым глазом** включает обратно. Подсказка при наведении показывает доступное действие. Выбор сохраняется для рабочего пространства после перезапуска VS Code. Эти же действия доступны через палитру команд как **TODO: Включить / Выключить подсветку в коде**.

Выделяется только маркер до закрывающей квадратной скобки включительно: `TODO[HIGH]`, `FIXME[MEDIUM]`, `BUG[CRITICAL]`. Двоеточие и описание не окрашиваются. Без приоритета выделяется только `TODO`, `FIXME` или `BUG`.

| Приоритет      | Цвет      |
| -------------- | --------- |
| CRITICAL       | Красный   |
| HIGH           | Оранжевый |
| MEDIUM         | Жёлтый    |
| LOW            | Синий     |
| Без приоритета | Серый     |

Подсветка обновляется вместе со списком задач и работает во всех видимых редакторах, включая разделённое окно. Поиск и фильтры боковой панели не скрывают подсветку в коде. Текст внутри строк и неподдерживаемые / исключённые файлы не выделяются. Для светлых, тёмных и высококонтрастных тем заданы отдельные цвета; при желании их можно переопределить через `workbench.colorCustomizations` по именам `todoManager.highlight.criticalBackground`, `todoManager.highlight.criticalForeground` и аналогичным для `high`, `medium`, `low`, `none`.

## Автоматическое обновление

При запуске сканируется проект, затем отслеживаются создание, изменение, удаление и переименование файлов. Несохранённые правки открытых документов также попадают в список; по умолчанию задержка составляет 300 мс. Поддерживаются рабочие пространства с несколькими папками. Закрытие документа с отказом от сохранения возвращает список к состоянию файла на диске.

По умолчанию исключены `node_modules`, `.git`, `dist`, `build`, `out`, `coverage`, `.next`, `vendor`, `.venv`, `venv`; файлы больше 1 МБ пропускаются. `.gitignore` автоматически не применяется. Двоичные и неподдерживаемые файлы не сканируются. Ошибки чтения отражаются в панели, детали доступны в **Output → TODO Manager**.

## Статусы и устойчивая идентификация

Статусы: **Открыта**, **В работе**, **Выполнено**, **Отложено**.

Для корректной привязки используется идентификатор в исходном комментарии:

```ts
// TODO[HIGH]: Добавить валидацию {#todo:15c8e401-d1ac-45f5-a663-7cd89f86648a}
```

Новые задачи сразу получают UUID. Для существующей задачи идентификатор добавляется при первом назначении статуса или редактировании через панель. Само сканирование файлы не изменяет. Статусы хранятся в `workspaceState` VS Code, а не по номерам строк: ID сохраняет привязку при добавлении строк, перемещении комментария и переименовании файла внутри того же рабочего пространства.

**Сохраняйте файл после назначения статуса**, чтобы ID остался на диске. При ручном редактировании не удаляйте ID. При копировании комментария удаляйте ID у копии. Если одинаковый ID всё же встречается несколько раз, задачи временно показываются открытыми; назначение статуса или редактирование выбранной копии выдаёт ей новый ID. Это предотвращает случайное присвоение одного статуса разным задачам.

Статусы локальны для данного рабочего пространства и профиля VS Code, между компьютерами и участниками команды они не синхронизируются. Если удалить комментарий, задача исчезнет из списка и статистики; запись статуса сохраняется, чтобы Undo или возврат комментария с прежним ID восстановили статус. Перенос в другое рабочее пространство не переносит локальную базу статусов.

## Языки и ограничения

Встроенные правила: JavaScript / TypeScript (включая JSX / TSX), C / C++, C#, Java, Go, Rust, Swift, Kotlin, Dart, PHP, CSS / SCSS / Less, JSONC, Python, Ruby, Shell, YAML, R, Perl, PowerShell, HTML / XML / SVG, Vue / Svelte (HTML-комментарии), SQL, Lua, Haskell, INI, Dockerfile, Makefile, TOML, BAT и LaTeX.

Используется лёгкий лексический анализатор, а не полноценные парсеры всех языков. Он пропускает строки, шаблонные строки и Python docstring. Сложные случаи — комментарии внутри выражений шаблонной строки, вложенные блочные комментарии, heredoc, смешанные языки в HTML/Vue/Svelte — могут требовать отдельных правил. В Vue/Svelte поддерживаются комментарии разметки `<!-- -->`; JS/CSS-комментарии внутри блоков не разбираются. JSON без комментариев и Markdown по умолчанию не сканируются. Для неизвестного языка команда создания выдаёт понятную ошибку вместо вставки угаданного синтаксиса.

Правила можно переопределить по `languageId` в настройках. Для файлов с нестандартным расширением дополнительно задайте `files.associations`; после открытия документа используется его `languageId`.

```json
{
  "todoManager.include": "**/*.{ts,tsx,js,py,html,css}",
  "todoManager.exclude": "**/{node_modules,.git,dist,build,generated}/**",
  "todoManager.maxFileSizeKB": 1024,
  "todoManager.debounceMs": 300,
  "todoManager.commentSyntax": {
    "myLanguage": { "line": ["//"], "block": [["/*", "*/"]] }
  }
}
```

Вставка и редактирование не сохраняют файл автоматически: это обычные изменения редактора. Удаление убирает только задачу; соседний код, другие маркеры и пояснения сохраняются.

## Статистика

Команда **TODO: Статистика проекта** или щелчок по счётчику TODO в строке состояния открывает отчёт: всего задач, файлов с задачами, выполненных задач, процент завершения и диаграммы по типам, приоритетам и статусам. Отчёт обновляется автоматически и всегда учитывает все найденные задачи, независимо от фильтров. Он показывает текущее состояние, а не историю удалённых комментариев. Скрипты в отчёте отключены, внешние ресурсы не загружаются.

## Разработка и проверки

Требуется Node.js 22 или новее и npm.

```sh
npm ci
npm test
npm run test:integration
npm run package
npm run test:package
```

Откройте проект в VS Code и нажмите **F5**: запустится отдельный Extension Development Host с папкой `examples`. Сборка запускается автоматически. Для разработки с пересборкой используйте `npm run watch`.

Модульные тесты проверяют синтаксис комментариев, строки, приоритеты, устойчивые ID, безопасное удаление, фильтры, сортировку и статистику. Интеграционный тест запускает два отдельных сеанса настоящего VS Code с временным профилем: проверяет несохранённые правки, переходы, CRUD, файловые события, группировку, поиск и сохранение статуса после перезапуска, перемещения строк и переименования файла.

На macOS интеграционный тест по умолчанию использует `/Applications/Visual Studio Code.app/Contents/MacOS/Code`. Для другой установки задайте переменную `VSCODE_EXECUTABLE_PATH`; на других ОС тестовая утилита скачивает VS Code, если путь не задан. Основной профиль и установленные расширения пользователя не меняются. `npm run test:package` повторяет интеграционные проверки для содержимого собранного VSIX, изолированного от зависимостей разработки (для распаковки нужна утилита `unzip`). Обычный тестовый режим `--extensionTestsPath` намеренно не используется: в VS Code он подменяет постоянное хранилище хранением в памяти.
